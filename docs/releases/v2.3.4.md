# v2.3.4 发布说明

v2.3.4 汇总自 v2.3.3 之后的 [PR #66](https://github.com/hs150521/JLCEDA-MCP-Community/pull/66)。MCP Server 与 EDA Bridge 应同时升级到 v2.3.4。

## Board 建立工作流

- 新增 `board_setup`。提供当前工程的 `projectUuid` 和 `confirm:true`，即可调用 EDA 官方 API 创建 Board，以及与它关联的新原理图和 PCB。
- 提供同工程、尚未关联 Board 的 `schematicUuid` 时，工具先创建新 PCB，再将现有原理图与新 PCB 关联到新 Board。
- 工具返回 Board 名称和两个文档的 UUID，并回读工程归属与关联关系。它不会自动打开文档，也不会将原理图变更导入 PCB。
- 如果写入结果不明，应先用 `bridge_recover_client` 对同一工程完整读取 Board、原理图和 PCB 目录，再决定是否继续；已创建的游离 PCB 不会自动删除。

## 安装与兼容

- 从同一个 GitHub Release 下载 `jlceda-mcp-server-2.3.4.tgz` 和 `mcp-bridge-community-2.3.4.eext`。运行环境需要 Node.js 20 或更高版本，并在 EDA 扩展管理器中启用“允许外部交互”。
- 扩展声明支持嘉立创 EDA 专业版 3.x。普通网络标签依赖 EDA v4 的 `createNetLabel`，因此 3.x 中仍会立即返回不支持；电源和地网络标识仍可使用。EDA v4 需等待明确兼容它的版本。

详细变更见 [Bridge 更新日志](../../mcp-bridge/CHANGELOG.md)和 [Server 更新日志](../../mcp-server/CHANGELOG.md)。社区版基于 [sengbin/JLCEDA-MCP](https://github.com/sengbin/JLCEDA-MCP) 改进，并非嘉立创官方插件。
